I did not set out to write any of this down. I started keeping notes because I kept solving the same problem twice — once badly, then again weeks later having forgotten the first attempt. The notes turned into posts, and writing them turned out to be the part that made the lesson stick.

Design is not just what it looks like and feels like. Design is how it works.

Steve Jobs

Most of what I have learned did not come from following a tutorial. It came from building something, watching it fail on a real device, and working backwards from the failure. That loop is slow and slightly humbling, and I have not found anything that replaces it.

Where it usually goes wrong

Almost every mistake I make has the same shape: I assume the happy path. The screen is wide enough, the image loads, the network is there, the visitor is using a mouse. The bugs live in the assumptions, not in the code I was concentrating on.

  • Start from the content, not from the layout grid.
  • Test on a real device before calling it responsive.
  • Keep the keyboard path working at every step.
